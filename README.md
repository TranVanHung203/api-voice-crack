# edge-tts

For deployment to a free Hugging Face Gradio/ZeroGPU Space, see
[DEPLOY_HUGGINGFACE.md](DEPLOY_HUGGINGFACE.md).

`edge-tts` is a Python module that allows you to use Microsoft Edge's online text-to-speech service from within your Python code or using the provided `edge-tts` or `edge-playback` command.

## Installation

To install it, run the following command:

    $ pip install edge-tts

If you only want to use the `edge-tts` and `edge-playback` commands, it would be better to use `pipx`:

    $ pipx install edge-tts

## Usage

### Basic usage

If you want to use the `edge-tts` command, you can simply run it with the following command:

    $ edge-tts --text "Hello, world!" --write-media hello.mp3 --write-subtitles hello.srt

If you wish to play it back immediately with subtitles, you could use the `edge-playback` command:

    $ edge-playback --text "Hello, world!"

Note that `edge-playback` requires the installation of the [`mpv` command line player](https://mpv.io/), except on Windows.

All `edge-tts` commands work with `edge-playback` with the exception of the `--write-media`, `--write-subtitles` and `--list-voices` options.

### Changing the voice

You can change the voice used by the text-to-speech service by using the `--voice` option. The `--list-voices` option can be used to list all available voices.

    $ edge-tts --list-voices
    Name                               Gender    ContentCategories      VoicePersonalities
    ---------------------------------  --------  ---------------------  --------------------------------------
    af-ZA-AdriNeural                   Female    General                Friendly, Positive
    af-ZA-WillemNeural                 Male      General                Friendly, Positive
    am-ET-AmehaNeural                  Male      General                Friendly, Positive
    am-ET-MekdesNeural                 Female    General                Friendly, Positive
    ar-AE-FatimaNeural                 Female    General                Friendly, Positive
    ar-AE-HamdanNeural                 Male      General                Friendly, Positive
    ar-BH-AliNeural                    Male      General                Friendly, Positive
    ar-BH-LailaNeural                  Female    General                Friendly, Positive
    ar-DZ-AminaNeural                  Female    General                Friendly, Positive
    ar-DZ-IsmaelNeural                 Male      General                Friendly, Positive
    ar-EG-SalmaNeural                  Female    General                Friendly, Positive
    ...

    $ edge-tts --voice ar-EG-SalmaNeural --text "مرحبا كيف حالك؟" --write-media hello_in_arabic.mp3 --write-subtitles hello_in_arabic.srt

### Custom SSML

Support for custom SSML was removed because Microsoft prevents the use of any SSML that could not be generated by Microsoft Edge itself. This means that all the cases where custom SSML would be useful cannot be supported as the service only permits a single `<voice>` tag with a single `<prosody>` tag inside it. Any available customization options that could be used in the `<prosody>` tag are already available from the library or the command line itself.

### Changing rate, volume and pitch

You can change the rate, volume and pitch of the generated speech by using the `--rate`, `--volume` and `--pitch` options. When using a negative value, you will need to use `--[option]=-50%` instead of `--[option] -50%` to avoid the option being interpreted as a command line option.

    $ edge-tts --rate=-50% --text "Hello, world!" --write-media hello_with_rate_lowered.mp3 --write-subtitles hello_with_rate_lowered.srt
    $ edge-tts --volume=-50% --text "Hello, world!" --write-media hello_with_volume_lowered.mp3 --write-subtitles hello_with_volume_lowered.srt
    $ edge-tts --pitch=-50Hz --text "Hello, world!" --write-media hello_with_pitch_lowered.mp3 --write-subtitles hello_with_pitch_lowered.srt

## Warm the Gwen/Yến Nhi cache from the TextVoice list

`data/gwen_cache/texts.json` contains **1,070 unique concrete texts** extracted
from `TONG_HOP_TEXTVOICE_KHOI_DONG_KHAM_PHA.md`. The warmer reads only this JSON
file; it does not read Dart or interpret Markdown instructions. Edit the array
to add/remove exact runtime text. Newlines and Vietnamese accents are preserved.
`pending_templates.json` reports 135 unresolved dynamic rows; these are not sent
literally to TTS. Technical/debug strings and supplementary UI/data tables are
excluded. `extraction_report.json` retains source locations and exclusions.

Run from PowerShell:

```powershell
cd F:\edge-tts
powershell -ExecutionPolicy Bypass -File .\warm_gwen_cache.ps1
```

The default URL is `https://tranvanhung203-edge-tts-api.hf.space`. Every request
uses GET `/tts` with `provider=gwen`, `voice=yen_nhi`, and `format=mp3`. The
script verifies `/gwen/voices` before starting, makes one request at a time,
retries transient failures, and stops after three consecutive failed texts.

```powershell
# Review the selected requests without calling the API:
.\warm_gwen_cache.ps1 -DryRun
# Test the first pending text:
.\warm_gwen_cache.ps1 -Limit 1
# Rewarm after the Space restarts or its server-side cache is cleared:
.\warm_gwen_cache.ps1 -Rewarm
# Override the destination or input file:
.\warm_gwen_cache.ps1 -BaseUrl http://127.0.0.1:8000 -TextsFile .\data\gwen_cache\texts.json
```

Successful receipts and local MP3 backups are saved under
`models/gwen_cache_warmup/` (`progress.jsonl` and `audio/`). Running again resumes
the remaining texts; `-Rewarm` starts a new progress batch and calls previously
successful requests again. If that batch is interrupted, rerun without
`-Rewarm` to continue the new batch.
`requests.jsonl` lists selected URLs; `preflight.json` records readiness/failures.
The local MP3 backup does not restore a remote server's cache automatically.
Space storage/cache can be reset by restarts or redeployment; use `-Rewarm`
after that. The server and app must request the same text/provider/voice.

No extra Python packages are required by the warm-up scripts. To regenerate the
extraction after updating the inventory, run:

```powershell
.\.venv-rvc\Scripts\python.exe .\tools\extract_textvoice_for_gwen.py
```

## FastAPI: Gwen-TTS (Yến Nhi)

[Gwen-TTS](https://github.com/ggroup-ai-lab/gwen-tts) is available on the same
GET `/tts` endpoint with `provider=gwen`. The default speaker is `yen_nhi`
(Yến Nhi). POST JSON `/tts` supports the same provider too.

Install the isolated Gwen environment once, then start the API as usual:

```powershell
cd F:\edge-tts
powershell -ExecutionPolicy Bypass -File .\setup_gwen.ps1
powershell -ExecutionPolicy Bypass -File .\start_server.ps1
```

GET example (paste into the browser or your client):

```text
http://127.0.0.1:8000/tts?provider=gwen&voice=yen_nhi&text=Xin%20chao&format=mp3
```

`voice`, `voiceid`, and `voice_id` accept either `yen_nhi` or `Yến Nhi`.
GET `/gwen/voices` lists all nine bundled speakers without downloading or
loading the model. Unknown speakers return 404; a missing runtime or inference
failure returns 503 with a diagnostic. `FORCE_VOICE_ID` applies to Gwen too;
set `FIXED_VOICE_ID` to a Gwen speaker when forcing that provider's voice.

Gwen runs in a persistent subprocess using `.venv-gwen`, because its
`transformers==4.57.3` dependency differs from the main API environment. Do not
install `requirements-gwen.txt` into `.venv-rvc`. The API starts the worker on
the first cache miss and retains the loaded model and speaker prompts. The
first request downloads the pinned model revision into `models/gwen/model`
(about a few GB for the complete runtime/model); CPU generation can be slow.
SDK/model versions and voice asset sources are in `voice_packs/gwen/README.md`.
The upstream source checkout is `vendor/gwen-tts` at
`f0f24d8636596dc635323e02f41bee42bb64385e`.

The runtime auto-selects CUDA if available, otherwise CPU with float32 and
SDPA attention. On an NVIDIA machine, run `setup_gwen.ps1 -Cuda` to install
CUDA PyTorch. FlashAttention is not required. Optional environment settings:

| Variable | Default | Purpose |
| --- | --- | --- |
| `GWEN_PYTHON` | `.venv-gwen/Scripts/python.exe` on Windows | Isolated runtime executable (absolute path recommended) |
| `GWEN_DEVICE` | `auto` | `cpu` or `cuda:0` to force a device |
| `GWEN_DTYPE` | `auto` | float32 on CPU, bfloat16 on CUDA; can be overridden |
| `GWEN_THREADS` | `4` | CPU thread count |
| `GWEN_TIMEOUT` | `900` | Maximum seconds per inference request, including initial loading |
| `GWEN_AUDIO_CACHE_DIR` | `models/gwen/audio_cache` | Persistent WAV and MP3 cache |
| `GWEN_MODEL_ID` | `g-group-ai-lab/gwen-tts-0.6B` | Model ID or complete local model directory |
| `GWEN_MODEL_REVISION` | pinned upstream revision | Override when intentionally updating model weights |

Restart the API after changing runtime/model settings. Worker diagnostics are
in `models/gwen/worker.log`. Existing audio is cached on disk with a 32 MiB RAM
limit; concurrent identical requests reuse one generation. GET supports ETags,
byte ranges, and HEAD. WAV is the default format; use `format=mp3` for MP3.
Text is normalized with `sea-g2p` and split into chunks of at most 320
characters before inference. `volume`, `pitch` and ZeroTTS's
`seed`/`eoa_extra_frames` do not affect Gwen.

Gwen supports an explicit `rate` through FFmpeg `atempo` after synthesis:
`rate=-20%` plays at 80% of the original speed; `rate=+0%` returns the original.
Accepted values range from `-50%` to `+100%`. Omit `rate` to keep Gwen's original
speed (the existing Edge rate defaults are not applied to Gwen). For example:

```text
/tts?provider=gwen&voice=yen_nhi&text=Xin%20chao&rate=-20%&format=mp3
```

This is audio postprocessing, not a native Gwen generation parameter. It aims
to preserve pitch but may affect timbre or smoothness; compare samples before
choosing a rate. FFmpeg is required for nonzero rates and is included in the
Space/Docker system packages. The source WAV stays unchanged; processed WAVs
are cached separately under `audio_cache/tempo`, and MP3 encoding happens
after tempo adjustment. Rate variants reuse the same model-generated source.

To make an offline listening comparison of the original, -10%, and -20% from
one Gwen/Yến Nhi WAV, run `.venv-rvc\Scripts\python.exe tools/demo_gwen_rate.py`.
Open `samples/gwen-rate/index.html` to listen. The script downloads one original
from the Space and processes it locally; `--source-wav path/to/original.wav`
reuses an existing recording. This comparison does not require redeploying.

Gradio Spaces install the isolated CPU environment and download the pinned
Gwen model before opening the API, using `setup_gwen.py` from `hf_app.py`.
The first startup can take several minutes; follow the Space runtime logs
until it prints `Gwen: isolated runtime and model files ready`. Failed installs
leave no ready marker and retry on restart. Docker performs this preparation
during the image build. Both profiles keep the API's transformers version separate.
On other Linux hosts, run `python setup_gwen.py --download-model` once.
`GWEN_PYTHON` can point to an existing isolated runtime; startup validates it
without installing into that external environment. Set `GWEN_AUTO_SETUP=0`
on a Gradio Space only when deliberately disabling automatic Gwen setup.

## FastAPI: VieNeu-TTS

[VieNeu-TTS](https://github.com/pnnbao97/VieNeu-TTS) v3 Turbo is available through
the existing GET/POST `/tts` endpoint with `provider=vieneu`. The SDK is pinned
to `vieneu==3.8.3`; a local source checkout is in `vendor/VieNeu-TTS`
(commit `bd0f88eb8de7d560753a6172ba9c868f309a101c`). To recreate the checkout:

```powershell
git clone https://github.com/pnnbao97/VieNeu-TTS.git vendor/VieNeu-TTS
git -C vendor/VieNeu-TTS checkout bd0f88eb8de7d560753a6172ba9c868f309a101c
.\.venv-rvc\Scripts\python.exe -m pip install -r requirements.txt
.\start_server.ps1
```

POST JSON example (WAV is the default; use `format=mp3` for MP3):

```json
{
  "provider": "vieneu",
  "text": "Xin chào, đây là giọng đọc VieNeu.",
  "voice": "Mai Anh",
  "format": "mp3"
}
```

Browser/GET example:

```text
http://127.0.0.1:8000/tts?provider=vieneu&text=Xin%20chao&format=mp3
```

GET `/vieneu/voices` lists preset names accepted by `voice`, `voiceid`, or
`voice_id`. Omit the voice to use the SDK default. Supplying an unknown name
returns 404. `FORCE_VOICE_ID` also applies to VieNeu requests; set the fixed ID
to a VieNeu preset name when using this provider.

The first VieNeu request loads the model and downloads any missing weights to
the Hugging Face cache (honors `HF_HOME`/`HF_HUB_CACHE`). Later requests reuse
the model. CPU/ONNX with fp32 and 4 threads is the default; set `VIENEU_THREADS`
to change the thread count. Inference runs in a worker thread and is serialized.
WAV output is mono PCM16 at 48 kHz. MP3 delivery uses the existing encoder and
`VIENEU_AUDIO_CACHE_DIR` (default `models/vieneu/audio_cache`). WAV audio is
cached on disk and in a 32 MiB RAM cache so repeated requests return the same
audio, including after a restart. Remove this directory after changing model
weights to regenerate audio. GET supports byte ranges and ETags, and HEAD
returns audio metadata.

To use a configured CUDA runtime instead, set `VIENEU_BACKEND=pytorch` and
`VIENEU_DEVICE=cuda` after installing compatible GPU dependencies following
the upstream README. Edge's `rate`, `volume`, `pitch` and ZeroTTS's `seed` and
`eoa_extra_frames` do not affect VieNeu. Other providers keep their current
routing; select VieNeu explicitly with `provider=vieneu`.

## FastAPI: V-TTS Zero-Shot

The API server also exposes non-streaming Vietnamese zero-shot voice cloning.
Install the server dependencies and start it from the repository root:

```powershell
pip install -r requirements.txt
uvicorn server:app --host 0.0.0.0 --port 8000
```

To force a server-owned voice ID, edit these settings near the top of `server.py`
and restart the server:

```python
FORCE_VOICE_ID = True
FIXED_VOICE_ID = "your-installed-voice-id"
FIXED_PROVIDER = None
```

When enabled, GET/POST `/tts`, `/vtts/synthesize`, and `/zerotts/synthesize`
ignore the client voice ID. `/tts` preserves explicit ZeroTTS/V-TTS provider
selection; use `provider=zerotts` for model voices such as `hamy` or `maichi`.
An Edge provider override is cleared to allow routing by the fixed ID.
Automatic routing selects ZeroTTS for a locally installed pack, otherwise V-TTS. The dedicated synthesis
routes retain their respective backends. An empty fixed ID returns HTTP 503.
Set `FORCE_VOICE_ID = False` (the default) to accept client voice IDs again.
Voice registration and reference-audio cloning keep their existing behavior.

Set `FIXED_PROVIDER` to `edge`, `vtts`, `zerotts`, `vieneu`, or `gwen` to
force the provider as well on GET/POST/HEAD `/tts` while `FORCE_VOICE_ID` is
enabled. For example, to always use Gwen/Yến Nhi:

```python
FORCE_VOICE_ID = True
FIXED_VOICE_ID = "yen_nhi"
FIXED_PROVIDER = "gwen"
```

`FIXED_PROVIDER = None` retains the routing described above. When
`FORCE_VOICE_ID = False`, both fixed settings are ignored. An invalid fixed
provider returns HTTP 503. Dedicated synthesis routes retain their backends.

Register a voice once by sending its reference recording to `POST
/vtts/voices`:

```bash
curl -X POST http://127.0.0.1:8000/vtts/voices \
  -F "voice_id=hung" \
  -F "reference_audio=@voice.wav"
```

The server extracts the speaker and prosody embeddings and persists them under
`models/vtts/voices`. Subsequent requests need only JSON text and the returned
`voice_id`:

```bash
curl -X POST http://127.0.0.1:8000/vtts/synthesize \
  -H "Content-Type: application/json" \
  -d '{"voice_id":"hung","text":"Xin chào, đây là giọng nói được nhân bản."}' \
  --output cloned.wav
```

`GET /vtts/voices` lists registered profiles. For one-off synthesis, `POST
/vtts/clone` is also available and accepts the text and reference in the same
request:

```bash
curl -X POST http://127.0.0.1:8000/vtts/clone \
  -F "text=Xin chào." \
  -F "reference_audio=@voice.wav" \
  --output cloned.wav
```

Registered voices can also be used through the existing `GET /tts` route by
passing only `text` and `voiceid`:

```bash
curl "http://127.0.0.1:8000/tts?text=Xin%20chào&voiceid=hung" \
  --output cloned.wav
```

When `voiceid` is omitted, `GET /tts` keeps its original Edge TTS behavior and
returns MP3. When `voiceid` is present, it uses the persisted V-TTS profile and
returns WAV, unless the ID belongs to an installed ZeroTTS pack.

Use a clean, single-speaker reference recording of about 3-10 seconds. WAV,
MP3, FLAC, and OGG files up to 25 MiB are accepted. Optional form fields are
`length_scale` (default `1.0`), `noise_scale` (default `0.667`), and
`noise_scale_w` (default `0.8`). Lower `length_scale` values speak faster.

The model is loaded on the first request and cached in memory. Model files are
stored under `models/vtts` by default. The following environment variables can
override the defaults:

- `VTTS_DEVICE`: `cpu` (default), `cuda`, or `auto`.
- `VTTS_MODEL_DIR`: directory used for downloaded model files.
- `VTTS_HF_REPO`: Hugging Face Space used to download the model files.
- `VTTS_CHECKPOINT_PATH`, `VTTS_CONFIG_PATH`, `VTTS_HASP_PATH`: explicit model
  file paths for offline deployments.
- `VTTS_TEMP_DIR`: temporary reference-audio directory.
- `VTTS_MAX_REFERENCE_BYTES`: upload limit in bytes.

V-TTS is licensed under CC BY-NC 4.0 and is restricted to non-commercial use
unless you obtain separate permission from its author.

## FastAPI: ZeroTTS voice packs

ZeroTTS is a separate, CPU-friendly ONNX backend. Install a downloaded ZeroTTS
voice ZIP once; do not unzip it manually:

```powershell
python -c "from zerotts_backend import zerotts_backend; print(zerotts_backend.install_voice_pack(r'C:\path\voice.zip'))"
```

Installed packs are stored under `models/zerotts/voices`. List them without
loading the model:

```bash
curl http://127.0.0.1:8000/zerotts/voices
```

Synthesize a WAV with the dedicated JSON endpoint:

```bash
curl -X POST http://127.0.0.1:8000/zerotts/synthesize \
  -H "Content-Type: application/json" \
  -d '{"voice_id":"VpYLlCQEgcoHgycJstNP","text":"Xin chao, day la ZeroTTS."}' \
  --output zerotts.wav
```

The existing GET route auto-detects locally installed ZeroTTS IDs:

```bash
curl "http://127.0.0.1:8000/tts?text=Xin%20chao&voiceid=VpYLlCQEgcoHgycJstNP" \
  --output zerotts.wav
```

The unified JSON route supports the same voice. Both `voiceid` and `voice_id`
are accepted:

```bash
curl -X POST http://127.0.0.1:8000/tts \
  -H "Content-Type: application/json" \
  -d '{"text":"Xin chao.","voiceid":"VpYLlCQEgcoHgycJstNP"}' \
  --output zerotts.wav
```

For clients that only have a `voice` field, putting the installed ZeroTTS ID in
that field is auto-detected too. Existing Edge TTS JSON requests remain
unchanged.

The server uses `audio_temperature=0.8` and retains one trailing codec
frame (`eoa_extra_frames=1`).
You can override `eoa_extra_frames` from `1` to `12` in JSON or as a GET query
parameter.

If a particular sentence sounds incomplete, generate another reading with the
optional `seed` parameter (an integer from 0 to 4294967295). It is supported by
GET/POST `/tts` and POST `/zerotts/synthesize` for ZeroTTS:

```json
{"text":"Trong bể có bao nhiêu con cá?","voiceid":"VpYLlCQEgcoHgycJstNP","provider":"zerotts","seed":7}
```

Omitting `seed` retains the existing server seed and cached output. Each explicit
seed has its own cache entry. The same text, voice, settings, and seed reproduce
the same reading on the same runtime; changing seed can improve one sentence
and worsen another. Listen to the result before selecting it. This does not
increase `min_frames`, change the text, or force extra speech after EOA.

For the isolated word `Năm` (also numeric `5`) with voice
`VpYLlCQEgcoHgycJstNP`, an omitted seed now selects the calibrated reading
`seed=11`. In the local hidden-continuation comparison, this reading finishes
its audible ending before the suffix cut, leaving about 80 ms for the release.
Capitalization, Unicode accent composition and terminal punctuation are accepted.
An explicit `seed` takes precedence. Other voices retain their defaults.
The effective seed is part of the cache key, so the earlier default reading is
not reused for this word. Restart the API to apply the change.

The exact prompt `Trên tờ lịch này có` uses `seed=7` for this voice when no seed
is supplied. With the default hidden continuation enabled, its internal model
text is `Trên tờ lịch này có; Bắt đầu thôi.`. This phrase boundary gives the
final `có` room to finish before the suffix is removed. The selected sample was
checked with ASR and Vietnamese CTC alignment; the fade starts after the aligned
end of `có`. Request/display text is unchanged. This rule accepts capitalization,
accent composition and terminal punctuation, but does not match longer sentences
or a newline that splits the phrase. Custom suffixes stay unchanged, and explicit
seeds take precedence. The effective seed and suffix select a new cache entry.

For the exact prompt `Đây là gang tay` with the same voice, the default reading
uses `seed=7`. With the default hidden continuation enabled, the model receives
`Đây là gang tay; Bắt đầu thôi.` to let the final `tay` finish before trimming.
Final delivery uses 100% speed (no whole-phrase tempo adjustment), after suffix trimming or
fallback, while preserving pitch. After verified suffix trimming, the aligned
final word `tay` is also lengthened at 75% speed, with a 10 ms crossfade into the
unchanged preceding speech. Only this final-word lengthening affects timing;
the rest of the phrase retains its original speed.
The ending calibration has its own cache version, so earlier short endings are
not reused. The lengthened source WAV and intermediate word audio are cached
and backed up to the configured Dataset. MP3 encoding uses the lengthened
waveform. Capitalization, accent composition and terminal
punctuation are accepted; longer sentences and other voices keep their speed.
FFmpeg is required and is already included in the Space/Docker packages.

### Built-in Hà My (hamy)

Use the model's identifier `hamy` for Hà My:

```json
{"provider":"zerotts","voice_id":"hamy","text":"Xin chào!","format":"mp3"}
```

Send this to `POST /tts`. The direct `POST /zerotts/synthesize` endpoint uses
the same body without `provider`. Common display spellings such as `Hà My`,
`Ha My`, and `ha_my` are accepted and resolve to the canonical `hamy` cache key.
The exact pinned standard model's eight built-in speakers are listed and
recognized for automatic routing before inference downloads/loads its weights.
The metadata catalog is ignored for a custom model or a different revision.

Keep `FORCE_VOICE_ID = False` in `server.py` to choose voices per request.
When forcing is enabled, `/tts` deliberately replaces the requested speaker and
provider with `FIXED_VOICE_ID` and `FIXED_PROVIDER` instead.

### Childlike copy of chi tham

Use the separate voice ID `VpYLlCQEgcoHgycJstNP_child` for a processed,
younger-sounding version of this speaker:

```json
{"text":"Hãy cùng khám phá nhé!","voice_id":"VpYLlCQEgcoHgycJstNP_child","format":"mp3"}
```

Send this body to `POST /zerotts/synthesize`, or add `"provider":"zerotts"`
for `POST /tts`. The source voice and its tuned short prompts are reused before
applying +3 semitones with resampling/tempo compensation at 100% tempo.
Vocal resonance follows the pitch shift. This revised profile avoids the
independent spectral-formant estimation used by the first preview.
This is an audio effect on the original speaker, not a retrained child voice.
It requires FFmpeg's [resampling and tempo filters](https://ffmpeg.org/ffmpeg-filters.html#atempo).

The processed WAV is cached separately in `voice_color/` and backed up under
`audio/voice_color/` in the configured private Dataset. MP3 delivery keeps its
existing separate cache. Source cache keys remain unchanged; the new voice
does not need another round of TTS inference for a source phrase already cached.
Pitch/processing changes invalidate only the processed derivative. The deployment
script also migrates local `voice_color/` files before updating the application.

Run `tools/demo_zerotts_child.py` with the existing warmup downloads to produce
three comparison samples from the cached source WAV under `samples/zerotts-child-v2/`
without calling TTS. Add `--long` for `samples/zerotts-child-v2-long/`.

Male childlike variants are also registered in the API:

| Voice ID | Source | Pitch | Tempo |
| --- | --- | --- | --- |
| `quangminh_child` | `quangminh` | +5 semitones | 100% |
| `tiendat_child` | `tiendat` | +4 semitones | 100% |
| `quangvinh_child` | `htSzITlVXGL3s4XwNqOv` (Quang Vinh, Southern) | +4 semitones | 100% |

The recommended pair is `tiendat_child` and `quangvinh_child`. The latter uses

Audio responses for ZeroTTS, VieNeu, and Gwen include
`X-Audio-Duration-Seconds` (for example `2.355`) alongside the WAV/MP3 bytes.

is also returned for cached audio, HEAD, byte ranges, and ETag revalidation.

`response.blob()`. No extra request field is needed. If duration metadata
cannot be read from an older file, the header is omitted and playback still
works; a browser can use `audio.duration` after `loadedmetadata` as a fallback.

### Smaller downloads and device caching

For ZeroTTS, add `format=mp3` to GET `/tts`, or `"format":"mp3"` to either
JSON synthesis endpoint. Omitting it retains WAV output. Edge/V-TTS routing
keeps its existing formats; the new format option is specific to ZeroTTS.

```bash
curl "http://127.0.0.1:8000/tts?text=Xin%20chao&voiceid=VpYLlCQEgcoHgycJstNP&provider=zerotts&format=mp3" --output speech.mp3
```

MP3 is mono at 64 kbps and uses lossy compression after suffix trimming.
Generation settings, voice data, and the original WAV stay unchanged. A measured
5.22-second sample shrank from 501,088 to 42,284 bytes; decoding the MP3 retained
all 250,522 source samples at 48 kHz. PyAV encodes in process and is included
in both requirements profiles; FFmpeg remains a fallback. Encoded output is
cached by the exact WAV content and encoding profile, with a bounded RAM cache
and disk files alongside the WAV cache.

GET/HEAD ZeroTTS responses include an ETag and `Cache-Control: private, no-cache`.
Devices may store the audio, but revalidate the URL before reuse. A matching
`If-None-Match` returns HTTP 304 without transferring the audio again. This
policy also detects new audio after a voice, seed, or backend setting changes
without relying on the caller to rename the URL. POST responses remain
`no-store`. GET byte ranges return 206, and HEAD provides length/ETag without
an audio body. CORS exposes the relevant headers.

ZeroTTS cache hits now bypass the inference lock; misses remain serialized and
simultaneous identical requests still generate once. The first uncached phrase
still needs TTS/alignment, and its first MP3 request also performs encoding.
For Flutter mobile, an HTTP audio player may need an explicit local file cache
to reuse downloads; the smaller MP3 response helps even without that cache.

### Optional hidden continuation

For local Windows use, `start_server.vbs` launches `start_server.ps1`, which
selects `.venv-rvc`, enables hidden continuation, and reuses downloaded diagnostic
models. Stop an existing server before launching it. Run
`powershell -NoProfile -File .\start_server.ps1 -CheckOnly` to inspect its Python
environment and settings, or pass `-DisableHiddenSuffix` to use the old flow.
Direct uvicorn/Hugging Face startup still uses the backend's opt-in configuration.

This experimental backend option uses `.Bắt đầu thôi.` **after chunking**.
Its leading period replaces the normalized segment's terminal punctuation in
the internal model text. For example, the model
receives `Trong bể có bao nhiêu con cá.Bắt đầu thôi.` without any intervening space. API input, displayed text,
and the original text used by the audio cache remain unchanged.

For isolated `Không` (including numeric input `0`), `Ba`, and `Năm` segments,
the default suffix uses a comma pause: `Không, Bắt đầu thôi.`,
`Ba, Bắt đầu thôi.` / `Năm, Bắt đầu thôi.`. This gives these short words a
phrase boundary before the continuation instead of shortening their ending.
The exception is applied after chunking and only with the default suffix;
counting lists, longer sentences, custom suffixes, and disabled mode keep their
existing behavior. The API/display text stays unchanged. The cache version
includes this rule so old audio for these words is not reused.

The period separates the original text from the hidden words.
They stay in the same model call as the original speech. ZeroTTS has no timed
pause argument here, so the pause duration depends on the generated waveform;
repeated spaces or newlines alone cannot enforce a pause. Alignment still
uses only the spoken words, and trimming uses the detected suffix boundary.

The end of the ASR word immediately before the suffix is protected from
cutting and fading, regardless of its spelling. This also protects the spoken
vowel of a single-letter label such as `B`, whose CTC character may occupy
only one emission frame. An overlapping or unusable cut boundary still uses
the old flow.

The option is **off by default**. Install its dependencies in the same Python
environment as the server:

```powershell
py -3.11 -m pip install -r requirements-hidden-suffix.txt
$env:ZEROTTS_ENABLE_HIDDEN_SUFFIX = "1"
$env:ZEROTTS_HIDDEN_SUFFIX = ".Bắt đầu thôi."
$env:ZEROTTS_SUFFIX_DEBUG = "1"
```

`ZEROTTS_SUFFIX_DEBUG=0` disables successful-request debug logs. Detection
failures still generate a warning. Set `ZEROTTS_ENABLE_HIDDEN_SUFFIX=0` and
restart the server to use the existing path without continuation or ASR.

Optional model selectors:

- `ZEROTTS_SUFFIX_ASR_MODEL`: faster-whisper model name or existing directory;
  default `small`, on CPU with int8 inference.
- `ZEROTTS_SUFFIX_ALIGN_MODEL`: a compatible Vietnamese character CTC model
  name or existing directory; default
  `nguyenvulebinh/wav2vec2-base-vietnamese-250h`.

Whisper confirms that the entire suffix occurs at the end of the spoken audio.
**The original speech is not compared with the request text.** For example,
Whisper hearing `Hãy đùa giấu lớn nhé` instead of `Hãy đồ dấu lớn nhé` does
not reject the suffix. Independent CTC transcription of the original is also
not an acceptance condition. This mode locates the hidden suffix; it does not
validate whether ZeroTTS pronounced every requested word correctly.

The recognized prefix is used only as acoustic context for Vietnamese CTC
forced alignment, which locates the first character of `Bắt`. ASR integer
tokens are expanded to spoken Vietnamese words for the alignment transcript.
If ASR recognizes only the suffix, alignment is restricted to a window starting
40 ms before its ASR timestamp; it does not force the suffix onto the start of
the original audio. Suffix recognition confidence, CTC confidence, and agreement
between the ASR word interval and CTC onset are still required.

This is forced alignment, not an estimate from total WAV duration. Alignment
uses a temporary 16 kHz copy; output retains the original 48 kHz sample rate
and WAV PCM 16-bit format. It does not change ZeroTTS weights, voice latents,
min_frames, EOA behavior, or sampling settings.

The cut starts from 20 ms before the aligned onset. A bounded search prefers
low-energy points, then snaps to a nearby zero crossing (within 1 ms). The
complete 15 ms fade-out must fit after the protected preceding word end.
Missing/uncertain suffix recognition, invalid/low-confidence suffix alignment,
an unsafe boundary, unavailable dependencies, or audio over 29 seconds uses
the old original-text flow. A spelling mismatch in the original alone does
not trigger fallback. The suffix cache version has changed so previous audio
is not reused with the new detection behavior.
The backend restores its random-state checkpoint before
regenerating, and never returns the untrimmed hidden suffix. Successful fallback
audio uses the same requested voice and is cached under the active workaround
settings, just like successfully trimmed audio. Repeated requests reuse this
final waveform from RAM, disk, or the configured Dataset instead of rerunning
ASR and fallback synthesis. Model failures that return no audio are not cached.
Changing text, voice, seed or suffix settings selects a different cache entry.
Successful cache entries include
the suffix, model selections, cut settings, and local model fingerprints.

The alignment model used for this experiment is licensed **CC BY-NC 4.0**;
review its [model card](https://huggingface.co/nguyenvulebinh/wav2vec2-base-vietnamese-250h)
before commercial use. Loading ASR and alignment models also adds CPU/RAM and
latency. No recognition models are loaded while the option is disabled.

Generate the five supplied sample sentences in the existing local environment:

```powershell
.\.venv-rvc\Scripts\python.exe tools/test_hidden_suffix.py --debug
```

To test a specific sentence, add `--text "một,hai,ba,bốn"` (repeat `--text`
for multiple sentences) and optionally `--output models/zerotts/hidden-suffix-counting`.
Use `--suffix ".Bắt đầu thôi."` to explicitly select the period and suffix.
Suffixes without a leading comma or period are appended verbatim. Results from suffix
comparisons should use separate output directories.

The test script reuses the existing diagnostic model directories when present;
otherwise use `--asr-model` and `--alignment-model`, or the environment variables
above. By default it writes to `models/zerotts/hidden-suffix-test/`:

- `before_cut/`: complete ZeroTTS audio including the hidden suffix.
- `after_cut/`: cropped segment WAVs plus `01_final.wav` through `05_final.wav`.
- `legacy/`: original-text-only WAVs with the same seed/settings for comparison.
- `results.json`: source/model text, status, suffix/cut timestamps, aligned words,
  and fallback reasons.

`before_cut/` also saves float32 `.npy` samples for exact ASR replay.
`--reuse-before` prefers these samples when present, otherwise reads the WAV;
it re-runs detection without regenerating TTS. PCM16 rounding alone may change
a recognizer's spelling of a short word. All normal runs bypass the audio cache. The optional workflow
buffers the complete segment and does not add a streaming API.
Sampling uses the configured fixed seed (the `_SAMPLING_SEED` constant in
`zerotts_backend.py`) to repeat readings for the same inputs and runtime.
Sampling defaults are `cfg_scale=1.0` (Voice Similarity),
`audio_temperature=0.8` and `audio_repetition_penalty=1.2`.
The backend normalizes Vietnamese text and punctuation, then generates each
sentence separately using the same voice and sampling settings. Long sentences
are split further at commas or word boundaries using ZeroTTS's chunker.
`max_chunk_sec=15` estimates the chunk size at 15 characters per second; actual
speech duration varies. Chunks are joined with 200 ms of added silence, without
changing speech speed or pitch. The fixed seed initializes sampling once per
request, with the random sequence continuing across chunks.
`max_frames=1500` limits each chunk. Chunking reduces the amount of text the
model must generate at once, but cannot guarantee complete words or a consistent
dialect from the model.
To change the minimum frames per chunk, edit `_MIN_FRAMES = 4` near the top of
`zerotts_backend.py` and restart the server. This value is included in the cache
key, so changing it generates new audio.
Text-token sampling temperature is controlled by `_TEXT_TEMPERATURE = 1.0`
in the same file. Restart the server after changing it; this also changes the
audio cache key.
`POST /zerotts/synthesize` accepts overrides for sampling and `max_chunk_sec`.
Both `/tts` routes use the default 15-second estimate automatically.
The cache version was updated so previous whole-text audio is not reused.
For a near-silent gap of 160-800 ms just before short final speech, the backend
keeps both gap edges and reduces the gap to 80 ms within each chunk. Speech samples are preserved;
earlier pauses, trailing silence and explicit punctuation in the last three
words are left unchanged. `_TAIL_PAUSE_MS` in `zerotts_backend.py` controls
this correction; set it to `0` to disable it. This is a conservative waveform
heuristic and does not identify words. Cache keys include the correction setting,
so changing it regenerates audio rather than returning an older cached result.

ZeroTTS caches generated WAV audio under `models/zerotts/audio_cache` (or
`ZEROTTS_DATA_DIR/audio_cache`). Both `/tts` and `/zerotts/synthesize` reuse
the same cache. Cached audio survives server restarts and can be returned
without loading the model; recent audio is also kept in a bounded 64 MiB RAM
cache. The key includes text, voice, seed, generation settings, model/runtime
configuration and local model/voice file fingerprints. Changing these inputs
generates a new entry. To regenerate previously cached audio, stop the server,
remove the files in the audio cache directory, then restart it.

Use `provider=edge`, `provider=vtts`, or `provider=zerotts` to select a backend
explicitly. The ZeroTTS model is downloaded on its first synthesis request and
cached under `models/zerotts/cache`; the installed voice list does not trigger a
model download.

Voice packs committed with the application can be placed under
`voice_packs/zerotts`. The provided `chi tham` pack is already bundled there, so
it remains available in Git, Docker, Render, and Fly deployments.

Configuration:

- `ZEROTTS_DATA_DIR`: root for the cache and installed voice packs.
- `ZEROTTS_BUNDLED_VOICES_DIR`: override the bundled voice-pack directory.
- `ZEROTTS_CACHE_DIR`: override the Hugging Face model cache directory.
- `ZEROTTS_MODEL_ID`: Hugging Face model ID (default `zeroweight-ai/ZeroTTS`).
- `ZEROTTS_MODEL_DIR`: use an already downloaded model directory.
- `ZEROTTS_REVISION`: optional Hugging Face revision or commit SHA.
- `ZEROTTS_PROVIDERS`: comma-separated ONNX Runtime providers.
- `ZEROTTS_THREADS`: ONNX CPU inference threads (default `4`).
- `ZEROTTS_WARMUP`: set to `0` to skip model warmup.
- `ZEROTTS_LOCAL_FILES_ONLY`: set to `1` to disable model downloads.
